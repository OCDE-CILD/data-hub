Methodology & Notes

Every dashboard on the OCDE Data Hub is built from data files published by the California Department of Education. Before those files reach a dashboard, OCDE's Research, Evaluation, and Data Insights (REDI) team runs each source file through a standardized cleaning pipeline: detecting and flagging suppressed values, standardizing school and district identifiers, mapping demographic groups to a consistent set of labels, and validating the result before it's published. This page documents that process in detail — including field-level suppression logic, encoding schemes, and known quirks or limitations by year — for anyone working directly with the downloadable data files. Click on any topic below to expand its notes.

General Data Handling

A handful of conventions are shared across nearly every file on this site:

  • Suppression detection. The specific mechanism has evolved over time. For most years, the columns subject to suppression in a given file are fixed in the cleaning script based on that file's known structure (e.g., a specific named list of count/rate columns to check). Starting with the 2024-25 refresh of some files, this was replaced with an automatic scan: every column is checked for the suppression marker, and whichever ones are found to contain it are treated as suppressible for that run. Either way, the result is the same kind of output — a suppression flag column, and the marker itself replaced with NA — so this mainly matters if you're comparing cleaning scripts across years rather than just using the published data.
  • Type coercion. Once suppressed values are set aside, remaining fields are coerced to numeric or integer types (integer when a column's non-missing values are all whole numbers, numeric when decimals are present), so downstream analysis doesn't have to first parse strings.
  • Demographic group standardization. Each source file uses its own internal numeric codes for student groups. These are remapped to a single canonical set of group labels and numeric codes (demo_group_num) used consistently across every file on this site, and the mapping is validated against a cross-tabulation of raw-to-canonical values to catch any group that fails to map cleanly. This is what lets you compare, say, English Learner outcomes across Chronic Absenteeism and Suspension files with confidence that "English Learner" means the same underlying group in both.
  • Organization level encoding. Records are tagged with a standard reporting-level code — org_level_num: State (1), County (2), District (3), School (4) — so the same file can support state-, county-, district-, or school-level analysis without separate files per level.
  • Charter & DASS status. Charter status is standardized as charter_num: Yes (1), No (0), All schools (2). Where a file distinguishes schools under alternative accountability status, the same pattern is used for dass_num.
  • County-District-School (CDS) codes. Location identifiers are padded to CDE's standard fixed-width CDS format and combined into a single cds field. Occasionally the same numeric code is issued at both the school and district level — an artifact of how CDE assigns codes, not a data error. When this happens, 99999 is added to the affected school-level code to disambiguate it from the district-level record, and the full list of altered codes is retained so the substitution can be traced back if needed.
  • Published file structure. The CSV available for download on this site is a user-facing version of the underlying fact table: internal modeling-only fields (alternate demographic group IDs, the pre-conflict-resolution CDS values) are removed, while the padded, usable identifiers (cds, the canonical demographic code) are retained so the file is still fully joinable to CDE's own published files.

Suppression

Suppression is checked at the row level, not field-by-field. For 2018-19 through 2023-24, the columns checked were a fixed list written into the script — enrollment_num, chronic_count, chronic_rate. Starting with the 2024-25 refresh, this switched to an automatic scan that checks every column for the asterisk marker rather than a fixed list — functionally similar in most cases, but able to catch a newly suppressed field that the fixed list wouldn't have anticipated. Either way, a single flag column, suppression (1/0), is set to 1 for a record if any checked column for that record contained an asterisk, which is then removed before the field is coerced to numeric.

Identifiers & CDS Codes

County-District-School (cds) codes are built and padded to a fixed width from the raw county/district/school codes. This resolution is applied to the fact table used to build the dashboard, but not to the "full" CSV. The full/flat CSV, the more human-readable export intended for outside analysts, has its cds column rebuilt from scratch after the conflict-resolution step, without reapplying the fix.

Year-over-Year QA Checks

Starting with the 2019-20 file, each new year is compared against the prior year's before cleaning begins: column names are checked for changes, and the set of columns subject to suppression is compared to catch any that were newly added or removed. From 2019-20 through 2022-23, an additional check compared the share of zero values for each field between the two years, flagging any field whose proportion of zeros shifted by more than 5 percentage points, a way of catching a meaningful change in reporting patterns beyond just suppression or renamed columns. In every year checked, these comparisons found no differences from the prior year serious enough to require a change to the cleaning process.

Areas & Composites

ELA has 4 area sections (Reading, Writing, Listening, and Research/Inquiry); Math has 3 (Concepts & Procedures, Problem Solving, and Communicating Reasoning). Math has no "area 4," and rows for that combination are explicitly dropped during cleaning rather than left as empty rows. Starting 2023-24, both ELA and Math also report 2 composite sections each; unlike the area sections, this page's source material didn't include the specific names of those composite sections.

Suppression

Suppression applies independently across up to three levels: core, area, and (from 2023-24) composite, each with its own enrollment-suppression and test-suppression flag, rather than one suppression flag for the whole record. In 2018-19, suppression was simple and consistent: within a given level, either every relevant column was suppressed or none were, and the only marker used was *. By 2021-22, suppression became more granular and the set of markers expanded to include *, an empty string, and NA — matching a similar evolution already described for CAST, though on a different timeline (CAST's equivalent change didn't happen until 2023-24).

Separately, mean_scale_score (Core only) can be blank for one of two different reasons, tracked with two distinct flags: blank_mean_score is set when the row is the "all grades" rollup, where CDE simply doesn't report a mean scale score by design, this is not suppression. mean_score_suppression is set when the value is genuinely suppressed for a specific grade/group due to small enrollment. This is the same distinction described for CAST, and the flag names are identical between the two files.

2023-24: Counts Added, Composite Introduced

Two significant changes arrived together in the 2023-24 file, the same year CAST gained similar changes:

  • Student counts were added alongside percentages for core, area, and composite results whereas 2018-19 through 2022-23 files contain percentages only.
  • Composite scores became their own exported fact tables (comp_ela / comp_math) for the first time. From 2018-19 through 2022-23, composite-related columns either didn't exist or were explicitly excluded during cleaning with a note that "composite doesn't exist this year."

Wide vs. Long Format

This is worth knowing if you're working with the downloadable data directly: the "full" CSV (the wide, human-readable export) keeps one row per school/district + student group + grade, with every achievement level as its own column (perc_met, perc_nearly, etc.), matching the shape of CDE's original file. The fact tables that power the dashboard are pivoted into long format instead: each achievement level becomes its own row, with a single core_achievement/perc column pair rather than one column per level. The downloadable CSV does not inherently match this structure.

Identifiers & Primary Keys

County-District-School (cds) codes are built and padded to a fixed width from the raw county/district/school codes. Where the same numeric code is used at both the school and district level, the school-level version is altered to keep the two distinct, and the list of affected codes is retained as altered_cds.

ELA and Math are always split into separate files at export (never mixed in one fact table). The primary key for the core fact tables is cds + demo_group_num + grade_num + core_achievement; for area, the same plus area + area_achievement; for composite (2023-24 onward), the same pattern using comp + comp_achievement.

Suppression

Like SBAC, suppression is tracked separately for enrollment and for test results, at both the core and area level. In 2018-19, the only marker used was *, and suppression was all-or-nothing within each group of columns, no partial suppression occurred. By 2021-22, the marker set had already expanded to *, an empty string, and NA — this change happened at some point between 2018-19 and 2021-22, not specifically in 2023-24 as an earlier version of this page stated.

Area suppression was not actually independent of core suppression until 2023-24. In 2021-22 and 2022-23, CAST's raw file had no area-specific enrollment data at all, so area enrollment suppression was calculated using the same core enrollment columns. Starting 2023-24, CDE began reporting per-subject enrollment totals (a1_total, a2_total, a3_total), which made independent area-level suppression possible for the first time. Within each level (core or area), the 2023-24 script explicitly confirms: enrollment being suppressed always means the test results are suppressed too, but test results can be suppressed on their own even when enrollment is visible.

Separately, mean_scale_score (Core only) can be blank for two different reasons, tracked with two flags in every year checked: blank_mean_score for the "all grades" rollup, where CDE doesn't report a mean scale score by design (not suppression), and mean_score_suppression for a suppressed value at a specific grade/group. This is identical to the same distinction in the SBAC file.

2018-19: Percentages Only

The 2018-19 file contains percentages only, there is no underlying count field, and percentages are not equal to percent × tested, so counts cannot be reliably back-calculated from this year's file. Percentages are converted to decimal proportions during cleaning (e.g., 68.7 becomes .687).

2023-24: Counts Added

Starting with the 2023-24 file, student counts were added alongside percentages for both core and area results which is the same change, in the same data year, as the SBAC (Math/ELA) file described elsewhere on this page. 2018-19 through 2022-23 contain percentages only.

As with SBAC, the downloadable "full" CSV keeps a wide shape, one row per school/district + student group + grade, with each achievement level as its own column. While the fact tables behind the dashboard are pivoted into long format, with achievement level as a row value rather than a column. The two aren't the same shape by design.
